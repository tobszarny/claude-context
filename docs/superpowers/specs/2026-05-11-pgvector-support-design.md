# PGVector Support Design

## Overview

Add PostgreSQL + pgvector as an alternative vector database backend for the MCP server. PGVector becomes a third option alongside Zilliz Cloud and Local Milvus, selectable via environment variable.

**Scope:** MCP server only. VS Code and Chrome extensions continue using Milvus REST.

## Architecture

### Approach

Minimal adapter: a new `PgvectorDatabase` class implementing the existing `VectorDatabase` interface. No changes to the `Context` class or `types.ts`. A simple factory switch in the MCP server selects between Milvus and PGVector based on an env var.

### New File

`packages/core/src/vectordb/pgvector-vectordb.ts` — `PgvectorDatabase` class using the `pg` npm package.

## Table Schema

Each Milvus "collection" maps to a PostgreSQL table. Column types mirror the Milvus field schema:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE {collection_name} (
    id VARCHAR(512) PRIMARY KEY,
    vector VECTOR({dimension}),
    content TEXT,
    "relativePath" VARCHAR(1024),
    "startLine" BIGINT,
    "endLine" BIGINT,
    "fileExtension" VARCHAR(32),
    metadata JSONB,
    content_tsvector TSVECTOR GENERATED ALWAYS AS (to_tsvector('english', content)) STORED
);

CREATE INDEX ON {collection_name} USING ivfflat (vector vector_cosine_ops) WITH (lists = 100);
CREATE INDEX ON {collection_name} USING GIN (content_tsvector);
```

- `metadata` uses native JSONB instead of a VARCHAR JSON string for better query performance.
- `content_tsvector` is auto-generated from `content` for full-text search.

## Hybrid Search Strategy

PGVector has no native BM25 sparse vectors. The hybrid search gap is bridged as follows:

- `createHybridCollection` creates the same table as `createCollection` (the `content_tsvector` column is always present).
- `insertHybrid` delegates to `insert` — no sparse vector to store; the tsvector column is auto-generated by PostgreSQL.
- `hybridSearch` performs two queries internally:
  1. **Dense cosine search** via `ORDER BY vector <=> $query_vector LIMIT N`
  2. **Full-text search** via `ts_rank(content_tsvector, plainto_tsquery($query_text))` with a `LIMIT N`
  3. Results are combined using **Reciprocal Rank Fusion (RRF)** with `k=100`, matching the Milvus hybrid search behavior.

This means the `HybridSearchRequest` interface is handled internally — the dense request uses `anns_field: "vector"` (cosine) and the sparse request uses the query text for FTS. No sparse vectors are involved.

## Configuration

### New Environment Variables

| Variable | Purpose | Default |
|----------|---------|---------|
| `VECTOR_DB_PROVIDER` | Select backend: `"milvus"` or `"pgvector"` | `"milvus"` |
| `PG_CONNECTION_STRING` | PostgreSQL connection string (e.g., `postgresql://user:pass@localhost:5432/dbname`) | Required when provider is `pgvector` |

### Existing Variables (unchanged)

- `MILVUS_ADDRESS`, `MILVUS_TOKEN` — still used when `VECTOR_DB_PROVIDER=milvus`
- All embedding variables remain the same

## Wiring Changes

### `packages/core/src/vectordb/pgvector-vectordb.ts` (new)

```typescript
export interface PgvectorConfig {
    connectionString: string;
}

export class PgvectorDatabase implements VectorDatabase {
    constructor(config: PgvectorConfig) { ... }
    // All VectorDatabase methods implemented
}
```

### `packages/core/src/vectordb/index.ts`

Add exports for `PgvectorDatabase` and `PgvectorConfig`.

### `packages/mcp/src/config.ts`

Add to `ContextMcpConfig`:
- `vectorDbProvider: 'milvus' | 'pgvector'`
- `pgConnectionString?: string`

Read from env vars:
- `VECTOR_DB_PROVIDER` → `vectorDbProvider`
- `PG_CONNECTION_STRING` → `pgConnectionString`

### `packages/mcp/src/index.ts`

Replace the hardcoded `new MilvusVectorDatabase(...)` with a factory switch:

```typescript
const vectorDatabase = config.vectorDbProvider === 'pgvector'
    ? new PgvectorDatabase({ connectionString: config.pgConnectionString! })
    : new MilvusVectorDatabase({
        address: config.milvusAddress,
        ...(config.milvusToken && { token: config.milvusToken })
      });
```

## PGVector-Specific Behaviors

| Method | Behavior |
|--------|----------|
| `checkCollectionLimit()` | Always returns `true`. PostgreSQL has no Zilliz-style collection limit. |
| `getCollectionRowCount()` | Uses `SELECT count(*) FROM {table}`. |
| `listCollections()` | Queries `information_schema.tables` filtering by table name pattern `code_chunks_%` or `hybrid_code_chunks_%`. |
| `getCollectionDescription()` | Returns `pg_description` comment on the table, or the table name if no comment. |
| `query()` | Translates Milvus filter expressions to SQL WHERE clauses for standard fields; uses JSONB operators for metadata filters. |
| `search()` | Uses `ORDER BY vector <=> $1::vector` with cosine distance operator. |
| `delete()` | Uses `DELETE FROM {table} WHERE id = ANY($1)`. |

### Filter Expression Translation

Milvus filter expressions (e.g., `fileExtension in [".ts", ".py"]`) need to be translated to SQL WHERE clauses. The implementation will handle common patterns:

- `field in ["a", "b"]` → `field IN ('a', 'b')`
- `field == "value"` → `field = 'value'`
- `metadata.key == "value"` → `metadata->>'key' = 'value'`

```markdown
#### Option 3: PostgreSQL + PGVector
- **PostgreSQL**: Version 12+ with the `pgvector` extension installed
```

## Out of Scope

- No VS Code or Chrome extension support (MCP server only)
- No auto-provisioning of PostgreSQL instances (user-managed)
- No migration tool between Milvus and PGVector
- No changes to the `VectorDatabase` interface or `Context` class
- No changes to collection naming conventions
